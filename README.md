# What can be measured determines what can be found

Code for: **What can be measured determines what can be found: creatinine measurement intensity and baseline provenance for acute kidney injury across fourteen data sources.**

Bongani Mbambara, [co-authors], Jifang Zhou. Pharmacoepidemiology Research Group (CPOR), China Pharmaceutical University, Nanjing.

Acute kidney injury (AKI) is defined by a rise in serum creatinine from a baseline, so a case can be found only in a patient who was measured, and only relative to whichever earlier value is chosen as the baseline. This repository extracts the complete creatinine series from fourteen critical care and perioperative data sources and quantifies how often and when creatinine is measured, where baseline values come from, and how much the choice of baseline changes who is called a case.

**1,261,700 patients · 5,451,085 creatinine results · 14 data sources · 6 countries**

All analysis code is in R.

## Repository layout

```
extraction/       R scripts that export each source to the common file specification
  institutional/  wrappers for the three Chinese institutional cohorts (ZD, NJF, AHMU)
analysis/         R pipeline that produces every number, table and figure in the paper
docs/             data specification, methods notes, proposed reporting checklist
results/          aggregate results as reported (no patient-level data)
```

## Reproducing the analysis

**1. Obtain the data.** Eleven sources are available to credentialed researchers through PhysioNet or their custodians (MIMIC-IV, eICU-CRD, AmsterdamUMCdb, HiRID, SICdb, NWICU, Zigong, PIC, VitalDB, INSPIRE, MOVER). The three institutional cohorts (ZD, NJF, AHMU) cannot be shared. No data are included in this repository.

**2. Export each source.** Run the matching script in `extraction/`. Edit the `path/to/...` placeholders at the top of each script to point at your local copy. Every script writes two files:

- `<SOURCE>_creatinine_series.csv` — one row per creatinine result
- `<SOURCE>_episode_covariates.csv` — one row per episode

See `docs/data_specification.md` for the column definitions. Do not open these files in Excel before analysis: it truncates at 1,048,576 rows without warning.

**3. Run the analysis** (R ≥ 4.3). Place the exported files in `analysis/data/`, then:

```bash
Rscript install_packages.R      # once: data.table, jsonlite, ggplot2, patchwork, scales, ragg
cd analysis
Rscript run_all.R               # per-source analysis, each source in its own R process
Rscript tables.R                # numeric tables  -> analysis/tables/
Rscript figures.R               # Figures 1-5 and Supplementary Figure 1 (PDF + 600 dpi TIFF)
Rscript graphical_abstract.R    # graphical abstract
```

`Rscript run_all.R MIMIC-IV INSPIRE` runs named sources only. The full run needs about 4 GB of memory and completes in under 15 minutes.

Tested with R 4.3.3, data.table 1.14.10, jsonlite 1.8.8, ggplot2 3.4.4, patchwork 1.2.0, scales 1.3.0, ragg 1.2.7.

## Key definitions

- **Hierarchy baseline** — most recent creatinine 7–30, then 31–90, 91–180, 181–365 days before the index episode (Guthrie et al., *Am J Kidney Dis* 2022).
- **Proximal baseline (tier 0)** — a value within 7 days before the index episode.
- **Post-index surrogate** — the minimum value within 24 hours after the index episode.
- **AKI** — KDIGO creatinine criteria: rise ≥0.3 mg/dL within 48 h or ≥1.5× baseline within 7 days. Urine output not applied.
